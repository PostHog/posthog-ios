**Breaking:** send analytics events to `/i/v1/analytics/events` (capture V1) with the project token as an `Authorization: Bearer` header instead of an `api_key` body field. Events the server accepts, warns about or drops are removed from the queue, and only the events it asks to retry are resent. On this endpoint only HTTP 408, 500, 502, 503 and 504 (and network errors) are retried; 429 and redirects are no longer retried. Capture follows only a 307 or 308 redirect to the origin of `host` (same scheme, host and port), at most 5 times; any other redirect drops the events, so point `host` at the final host. If the host returns 404 for the new endpoint, the SDK falls back to `/batch` until the app restarts. If you use a reverse proxy, forward `/i/v1/analytics/events`: only a 404 triggers the fallback, and other responses such as 403 or 405 drop the events. Capture requests replace any `Authorization` header from `requestHeaders`, so authenticate your proxy with a different header.

Add per-event capture options: `capture(..., timestamp:options:)` (Objective-C `captureWithEvent:distinctId:properties:userProperties:userPropertiesSetOnce:groups:timestamp:options:`) and `PostHogEvent.options`, which `beforeSend` can read and change. Known keys are `process_person_profile`, `cookieless_mode`, `disable_skew_correction` and `product_tour_id`; other keys are sent unchanged. The legacy `$process_person_profile`, `$cookieless_mode`, `$ignore_sent_at` and `$product_tour_id` properties are sent as their options instead of as properties, and an option you set wins over its legacy property. PostHog drops an event whose option value it can't read.
